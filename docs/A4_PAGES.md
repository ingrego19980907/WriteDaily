# A4 writing pages (ED.18)

Writing and read-only preview render the chapter as vertically stacked A4-proportion paper sheets (210 ? 297 mm at full screen width, scaled to fit narrower viewports). Margins scale from 20 mm, with a 24px inter-page gap and decorative page numbers. Text stays readable at its selected size instead of shrinking with the paper. The header and save controls remain outside scrolling writing.

Automatic pagination is a ProseMirror view plugin, not a document rewrite. It measures a hidden temporary clone at the editor width, finds rendered lines, and adds noneditable view decorations between lines or before blocks. Text, paragraph structure, marks, selection and undo history are preserved. Layout metadata never triggers a content save or word-count change. Measurement runs after document changes, width/font-size changes and font loading, waits for composition to finish and disconnects observers on unmount. Only writing-driven changes request caret scrolling; passive layout does not move the user's selection.

Add page appends an explicit pageBreak node and an editable paragraph at the chapter end, then focuses the new sheet. Current typing marks are retained. The button is unavailable during pending/blocked writes and is absent from read-only preview. Manual page breaks participate in normal undo/redo and use existing 2-second inactivity autosave, Ctrl+S and close/discard guards. Automatic sheets reflow as the available width and text formatting change; manual breaks remain anchored in content.

## Persistence

Content v6 adds an attribute-free, content-free pageBreak block only at the document root. It creates a word boundary without adding words. v1-v5 remain readable; serializers keep the oldest compatible content version. Existing byte/node/depth limits remain, and native saves still commit content/count/revision atomically. No SQL migration, dependency, document reset or real-library migration is performed. Older binaries safely reject content versions they cannot interpret.

## Scope and verification

This is the in-app writing surface, not a promise of Word file/print pagination equivalence. Browser font metrics determine wrapping; small screens preserve paper proportions and readable text, so their automatic page counts can differ. Export, print layout, running headers/footers and tables are separate future work. The measurement clone is short-lived and excluded from accessibility; decorative sheets are outside the editor and cannot enter copied/saved writing.

The implementation uses the existing ProseMirror [widget/node decoration API](https://github.com/ProseMirror/prosemirror-view/blob/master/src/decoration.ts). Browser tests check A4 proportions, actual text-line bounds on multiple sheets, unchanged editor JSON, manual-page cursor placement, save/reopen and preview restrictions. Shared TypeScript/Rust cases cover accepted and rejected page-break grammar, and a disposable database test verifies committed manual breaks, counts, rejected-write rollback and reopen. The em-sized observation probe also detects root text enlargement when paper dimensions do not change. All 565 Vitest, 119 Edge and 72 Rust tests passed; the final font-enlargement update was followed by another successful 565-test Vitest run and all three dedicated page browser cases. Lint, format:check, strict TypeScript/build, Cargo fmt/Clippy and diff checks passed. Detailed results are recorded in [ACCESSIBILITY_REVIEW.md](ACCESSIBILITY_REVIEW.md#ed18-a4-pages). No native GUI launch/restart is claimed for this maintenance task.
